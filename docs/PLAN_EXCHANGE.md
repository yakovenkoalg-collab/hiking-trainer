# Формат совместной корректировки

## Отчёт

Файл `*.mountain-report.json` схемы 5 содержит версию, период, идентификаторы тренировок, их фактическую длительность и статус достоверности времени, предстоящий план на 14 дней, подходы, статус использования таймера, план/факт отдыха, readiness, наблюдения боли, Garmin/FIT-активности, метрики тела, цели, текущие ограничения и активную контрольную точку. Для FIT дополнительно передаются круги/километровые отрезки, время в пульсовых зонах, Training Effect, нагрузка, настройки пульса и доступная беговая динамика.

Отчёт не включает фотографии и облачные credentials. Его можно явно отправить через системное меню «Поделиться» или синхронизировать в выбранное хранилище.

Полная резервная копия использует схему 3. Она включает новые FIT-показатели, но по-прежнему не включает фотографии, OAuth-токен и настройки доступа к папкам.

## Общая папка

Пользователь выбирает папку через Android Storage Access Framework. Обычно это папка на телефоне; облако появляется в системном выборе только если его Android-приложение зарегистрировало файловый провайдер. Поэтому этот способ считается локальным запасным вариантом, а для гарантированного обмена без USB приложение использует прямую синхронизацию с Яндекс Диском.

- `reports/current-report.json` — актуальный отчёт;
- `plans/inbox/` — новые планы для предпросмотра;
- `plans/applied/` — применённые планы;
- `backups/` — полные резервные копии без фото.

## Яндекс Диск

Прямой обмен использует те же подпапки внутри `app:/` — изолированной папки приложения на Яндекс Диске. Пользователь нажимает «Войти с Яндекс ID», подтверждает доступ в официальном LoginSDK, после чего полученный OAuth-токен шифруется ключом Android Keystore и никогда не экспортируется. Приложение не запрашивает чтение или запись остальных файлов Диска. Ручной ввод токена в основном интерфейсе отсутствует. Client ID является публичным идентификатором Android-приложения и задаётся при сборке; client secret, токен и ключ подписи не встраиваются в APK и не коммитятся. Инструкция: [YANDEX_ID_SETUP.md](YANDEX_ID_SETUP.md).

Автообмен ставится в локальную очередь WorkManager и ждёт сеть. Входящий план остаётся в `plans/inbox` до ручного preview и подтверждения; после применения переносится в `plans/applied`.

## План

Файл `*.mountain-plan.json` содержит полную версию будущих тренировок, причину изменений и ожидаемый период действия.

Новые поля упражнения имеют безопасные значения по умолчанию, поэтому планы v0.2 продолжают читаться. Для точного движка v0.3 следует передавать `blockId`, `blockTitle`, `blockType`, `sets`, `rounds`, `reps`, `workSeconds`, `restSeconds` и `restAfterRoundSeconds`.

Персональный план может задать `replacePlannedFromEpochDay` и `replacePlannedThroughEpochDay`. Тогда preview отдельно показывает старые запланированные тренировки в этом диапазоне, которые будут заменены. Диапазон автоматически ограничивается сегодняшним днём: прошлые даты и даты с выполненной тренировкой не принимаются даже при другом идентификаторе. При подтверждении удаляются только будущие записи со статусом `PLANNED`; выполненная и пропущенная история не удаляется и не переписывается.

## Безопасный импорт

1. Проверить версию схемы и обязательные поля.
2. Не изменять прошлые даты, даты с выполненной тренировкой, а также выполненные или пропущенные тренировки с тем же идентификатором.
3. Сопоставить упражнения с активными ограничениями.
4. Показать preview «было / станет» по каждой тренировке: дата, длительность, RPE, упражнения и структура подходов.
5. Применить только после явного подтверждения.
6. Сохранить ревизию и закрыть контрольную точку только после подтверждённого применения.
